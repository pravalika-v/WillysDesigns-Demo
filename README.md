# WillysDesigns — database-backed demo

A standalone Node.js 24 website with the supplied design and a contact-enquiry database supporting local SQLite or Turso Cloud. No package installation is required: the server uses Node's built-in HTTP and SQLite modules. Email delivery is intentionally disabled.

## Start locally

1. Install Node.js **24.14 or later in the 24.x series** (tested with 24.19.0).
2. Open a terminal in this folder.
3. Run `node server.mjs`.
4. Visit http://localhost:3000. Use the server URL, not a double-clicked HTML file.

The first start creates `data/enquiries.sqlite` automatically. Stop with Ctrl+C. Restarting keeps the enquiries. No demo records are shipped.

Optional: copy `.env.example` to `.env`, set your values, and start with `node --env-file=.env server.mjs`. The default start does not automatically read `.env`.

## Deploy on Render Free + Turso

Read **[TURSO-SETUP.md](TURSO-SETUP.md)** for database-token creation, Render environment settings, verification and later upgrades.

The included `render.yaml` selects Free with `DB_PROVIDER=turso`. It prompts for `TURSO_DATABASE_URL` and `TURSO_AUTH_TOKEN`; no disk is required. `PUBLIC_ORIGIN` should be set to the generated HTTPS origin after the service URL is known. No service has been deployed automatically.

The backend uses Turso's official SQL-over-HTTP API through Node's built-in fetch. There is no SDK dependency to install. Local development still defaults to SQLite. When using local SQLite on a cloud host, mount persistent storage at `/app/data` and set `DB_PATH=/app/data/enquiries.sqlite`. Free Render cannot preserve that local file. Do not deploy only `public/` as a static site.
### Docker locally

```sh
docker build -t willysdesigns-demo .
docker run --rm -p 3000:3000 -v willys-enquiries:/app/data willysdesigns-demo
```

The image version matches the Node version used for local tests. The Docker image itself has not been built in this workspace.

## Review and back up enquiries

In the project directory (or the hosting service's private shell):

```sh
node scripts/enquiries.mjs
node scripts/backup.mjs /path/to/private-backup.sqlite
```

The first command prints the latest 100 enquiries as JSON. It is an operator-only command, not a public API or admin dashboard. It uses the same database-provider environment variables as the server. For Turso, run this on your computer using a private `.env`; Render Free has no service shell. When using a local `.env`, add `--env-file=.env` after `node`.

The backup command is for SQLite only and rejects Turso mode. Use Turso's export tools for remote backups. For SQLite, it uses the online backup API so the backup includes committed data even while WAL mode is active. Keep backups private and copy them off the service's disk. Do not copy only the live `.sqlite` file while the server is writing; committed data can still be in its WAL file.

## Contact API

`POST /api/contact`, JSON:

```json
{
  "name": "Demo Customer",
  "email": "demo@example.com",
  "phone": "9000000000",
  "projectType": "Residential interiors",
  "message": "A sample enquiry for this demonstration.",
  "website": "",
  "requestId": "a8c862e5-638f-44d0-a6f8-dbb8a46cd028"
}
```

`requestId` is a UUID v4 generated by the browser. Success is returned only after the insert commits. Repeating the same request returns the original record ID instead of adding a duplicate. A changed payload with a reused ID returns 409. The browser retains its ID after a network error so retrying is safe within the same page session.

Limits: 100-character name, 254-character email, 30-character phone with 7–15 digits, 2,000-character message with at least 10 characters, fixed project-type choices, and 16 KB maximum request body. Invalid input returns 422. There is a honeypot, origin/fetch-site checking, and a 10-attempt/10-minute in-memory rate limit per connection address. Parameterized SQL is used. No enquiry list or database is exposed over HTTP.

`TRUST_PROXY_HOPS=0` is the safe default: forwarded client IP headers are ignored. Behind a proxy this can share a rate limit across visitors. Set a positive hop count only after verifying that your hosting ingress sanitizes the forwarded header and that clients cannot bypass that ingress. The rate limit is basic demo protection, resets on restart, and is not a substitute for managed abuse protection on a busy public site.

Run `node --test test/*.test.mjs`. It checks persistence across restart, duplicate handling, SQL input safety, validation, payload limits, rate limiting, private paths, redirects, video byte ranges, case-sensitive local links, merge markers and JavaScript syntax.

## Scope before a real business launch

This preserves the supplied template and demo content. Some article/project-detail links remain template placeholders; no blog CMS, project detail pages or admin login has been invented. Confirm the business phone number, opening hours, project imagery, testimonials, awards and theme/asset licenses before publishing as a real business site. The original large images and much of the exported theme remain, so further performance and dependency cleanup is a separate follow-up.

Use sample enquiries for this demo. Establish an actual retention/deletion policy and production privacy notice before collecting customer details. Email settings can be added later without changing the stored enquiry schema.
